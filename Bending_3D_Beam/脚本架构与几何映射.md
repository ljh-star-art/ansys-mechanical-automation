# Bending_3D_Beam：脚本职责与几何映射思路

## 1. 当前脚本的职责

| 脚本 | 职责 | 是否每次求解都需要运行 |
|---|---|---|
| `inspect_mechanical_objects.py` | 列出分析树中的对象，确认是否存在 `Pressure`、`FixedSupport`、`Solution` 等对象 | 否。模型结构变化后或开发诊断时运行 |
| `inspect_load_properties.py` | 读取载荷对象的类型和属性，例如 `Magnitude`、`Location`、`LoadedArea`、`DefineBy` | 否。用于确认 Mechanical 2024 R2 的 API |
| `test_pressure_assignment.py` | 将一个已知压力值写回 Pressure 对象，验证赋值 API 是否可用 | 通常只运行一次 |
| `case_spec.py` | 读取 `case_config.json`，转换数据类型并校验参数范围 | 是。由外部 Python 流程调用 |
| `pymechanical_model_test.py` | 启动 Mechanical、加载 `SYS.mechdb`、把配置参数传入 Mechanical，并调用内部脚本 | 是 |
| `run_static.py` | 在 Mechanical 内找到已有 Pressure 对象，修改其 `Magnitude`，划分网格、求解并写出结果 | 是 |
| `analyze_results.py` | 读取结果 JSON，输出关键结果并判断是否超过应力限值 | 是 |
| `run_pipeline.py` | 按顺序调用求解脚本和结果分析脚本 | 一键入口 |

## 2. 当前数据流

```text
case_config.json
        ↓
case_spec.py：读取、类型转换、参数校验
        ↓
pymechanical_model_test.py：启动 Mechanical 并传递参数
        ↓
run_static.py：访问 Mechanical 模型树
        ↓
找到已有 Pressure 对象，保留原 Location
        ↓
修改 Pressure.Magnitude
        ↓
生成网格并求解
        ↓
latest_results.json
        ↓
analyze_results.py：结果判断
```

`inspect_*` 脚本属于开发阶段的“侦察工具”。它们帮助确认模型对象的名称、类型和 API 属性；正式求解时主要执行 `run_static.py`，而不是再次执行诊断脚本。

## 3. 为什么当前脚本能保留几何位置

当前模型已经在 Mechanical 中手动建立了 Pressure 和 FixedSupport，并且这些对象已经绑定到具体几何实体。脚本执行：

```python
pressure.Magnitude = Quantity("30000 [Pa]")
```

只修改载荷大小，不修改 `pressure.Location`。因此原来绑定的受力面会被保留。当前项目并没有让 LLM 根据文字直接猜选面。

## 4. 自然语言到几何位置的目标流程

用户输入：

```text
我要做弯曲梁静力分析，左端固定，右端施加 30000 Pa 压力。
```

未来的智能体应执行：

```text
自然语言
  ↓
LLM 提取意图：载荷类型、数值、方向、左端/右端等
  ↓
转换为结构化 CaseSpec
  ↓
读取模型的 Named Selection 或几何实体信息
  ↓
把“左端”“右端”映射到具体选择
  ↓
让用户确认映射结果
  ↓
Mechanical API 创建或修改 FixedSupport、Pressure/Force
  ↓
网格、求解、结果检查
```

LLM 不应凭空猜测几何位置。推荐的实现层次如下：

1. **Named Selection（推荐）**：预先建立 `fixed_left_end`、`load_right_end`，智能体只需将自然语言映射到这些名称。
2. **坐标/包围盒规则**：读取几何范围，用最小或最大 X 坐标识别左端、右端，适合规则梁。
3. **几何候选列表 + 用户确认**：工具返回面 ID、中心坐标和面积，LLM 选择候选面后必须让用户确认。
4. **保留已有对象位置**：对于已经人工建好的模型，最安全的方式是只修改 `Magnitude`，不重新选择几何。

## 5. 当前项目的边界

当前已实现：

- 网格尺寸由配置控制；
- `pressure_value_pa` 真正写入已有 Pressure 对象；
- 原有载荷位置和固定支撑位置被保留；
- 求解结果写入标准 JSON。

当前尚未实现：

- 从自然语言自动创建几何选择；
- 自动把“1000 N”换算为压力并计算受力面积；
- 自动创建新的载荷或约束对象；
- 复杂模型中的通用几何识别。

因此，当前路线是先实现“参数化已有模型”，再逐步增加 Named Selection、几何识别和自然语言交互。

## 6. 当前模型中的空间位置是如何处理的

当前项目并没有让 LLM 自动识别“左端面”或“右端面”。空间位置是在 Mechanical 中手动建立 Pressure 和 FixedSupport 时确定的，并由 Mechanical 保存到 `SYS.mechdb`。

实际过程是：

```text
在 Mechanical 中手动选择左端面并创建 FixedSupport
        ↓
手动选择受力面并创建 Pressure
        ↓
Mechanical 将几何选区保存到 SYS.mechdb
        ↓
PyMechanical 打开 SYS.mechdb
        ↓
run_static.py 找到已有 Pressure 对象
        ↓
只修改 Pressure.Magnitude
        ↓
原来的受力位置保持不变
        ↓
重新划分网格并求解
```

`run_static.py` 中的核心逻辑是：

```python
analysis = Model.Analyses[0]
for child in analysis.Children:
    if "Pressure" in str(child.DataModelObjectCategory):
        pressure = child
        break
pressure.Magnitude = Quantity("30000 [Pa]")
```

这段代码表示“找到已有 Pressure 对象并修改压力值”，并不表示“根据右端这个词重新寻找右端面”。因为没有修改 `pressure.Location`，所以原来绑定的几何位置会被保留。

## 7. 自然语言在当前版本中的实际作用

当前版本还没有完整的自然语言几何解析器。目前的流程更接近：

```text
用户或 Codex 修改 case_config.json
        ↓
CaseSpec 读取、类型转换和校验
        ↓
PyMechanical 将参数传入 Mechanical
        ↓
run_static.py 修改已有载荷并求解
```

例如用户表达：

```text
我要做弯曲梁分析，压力为 30000 Pa，网格尺寸为 0.005 m。
```

未来可以将其转换成：

```json
{
  "element_size_m": 0.005,
  "pressure_value_pa": 30000,
  "load_direction": "negative_y",
  "constraint": "fixed_left_end"
}
```

但其中的 `fixed_left_end` 目前仍然表示已有模型中的约束名称，不表示智能体已经重新识别了左端几何。

## 8. 真正自动识别几何位置所需的功能

如果用户说“左端固定，右端施加压力”，智能体还需要一个几何选择层，将自然语言位置映射为具体几何实体。可以采用：

1. **Named Selection**：预先建立 `fixed_left_end` 和 `load_right_end`，智能体将自然语言映射到这些名称。这是最推荐的方式。
2. **坐标规则**：读取几何包围盒，以最小 X 坐标识别左端、最大 X 坐标识别右端，适合规则梁。
3. **候选几何 + 用户确认**：工具返回面 ID、中心坐标和面积，由 LLM 选择候选面，再让用户确认。

不应让 LLM 在没有几何数据的情况下凭空猜测位置。可靠流程应为：

```text
自然语言
  ↓
LLM 提取载荷类型、数值、方向和位置意图
  ↓
转换为结构化 CaseSpec
  ↓
读取 Named Selection 或几何实体信息
  ↓
将“左端/右端”映射到具体选择
  ↓
用户确认
  ↓
Mechanical API 创建或修改对象
  ↓
网格、求解和结果检查
```

因此，当前智能体主要负责理解任务、组织参数、调用 PyMechanical/MCP、启动求解和解释结果；空间位置仍由手动模型中的几何绑定提供。这是第一阶段更安全、可验证的实现方式。
