# Bending 3D Beam 模型初始化

本案例的 Python 脚本需要 ANSYS Workbench 生成的 Mechanical 数据库。该数据库位于 `beam_files` 目录中，而 `beam_files` 默认被 `.gitignore` 排除，因此克隆仓库后需要先执行一次初始化。

## 克隆后的初始化流程

1. 安装 ANSYS Mechanical 2024 R2，并确认许可证可用。
2. 安装 Python 依赖：

   ```powershell
   python -m pip install -r requirements.txt
   ```

3. 在资源管理器中打开：

   ```text
   Bending_3D_Beam\beam.wbpj
   ```

4. 在 Workbench 中打开 `Static Structural` 系统的 `Model`。
5. 确认 Mechanical 中存在几何体、材料、约束和载荷。
6. 如果项目提示更新或重新生成，执行更新并保存项目。
7. 在 Mechanical 中生成网格并求解一次，然后保存并关闭 Workbench。
8. 确认以下文件已经生成：

   ```text
   Bending_3D_Beam\beam_files\dp0\global\MECH\SYS.mechdb
   ```

9. 确认 `pymechanical_model_test.py` 中的 `MECHANICAL_EXE` 指向本机的 `AnsysWBU.exe`。
10. 运行自动化流水线：

    ```powershell
    python .\Bending_3D_Beam\run_pipeline.py
    ```

## 说明

`beam.wbpj` 是 Workbench 项目入口，`SYS.mechdb` 是 Mechanical 数据库。PyMechanical 当前直接加载 `SYS.mechdb`，因此仅有 `beam.wbpj` 而没有 `beam_files` 时，不能立即运行 `pymechanical_model_test.py`。

`beam_files` 中包含 ANSYS 生成的网格、求解数据库、缓存和日志。这些文件与 ANSYS 版本、机器环境和求解状态有关，通常不提交到普通 Git 仓库。

## 初始化检查命令

在运行流水线前，可以检查数据库是否存在：

```powershell
Test-Path .\Bending_3D_Beam\beam_files\dp0\global\MECH\SYS.mechdb
```

输出 `True` 后再执行流水线。输出 `False` 时，先完成上面的 Workbench 初始化步骤。

## 当前项目的限制

该初始化流程依赖本机安装的 ANSYS Mechanical 2024 R2 和许可证，不能仅依靠 GitHub 上的 Python 文件完成。若需要完全自动初始化，应在后续版本中增加 Workbench/PyMechanical 的模型创建脚本，或者使用 Git LFS 保存经过验证的模型数据库。
